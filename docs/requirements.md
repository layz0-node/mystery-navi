# シーシャ屋ミステリーナビ 要件定義（確定版 v7）

作成：2026-11-05
元にしたもの：2026年3月の要件定義・画面設計・Claude Code指示書 ＋ 2026年11月の見直し（7回）

v6からの主な変更（開発前の総点検による）
- 到着したら「到着済み」を保存し、評価するまで（翌朝5時と到着から3時間後の遅いほうまで）到着画面を保つようにした。吸い終わってから評価できる
- 到着画面に「評価せずに別のお店へ」を置いた
- 取り消しと昇格のお知らせを、圏外画面にも出すようにした
- 案内中だけ画面が自動で消えないようにした
- 方位の表記を N・E・S・W にした
- デバッグに「仮の目的地」を足した（実機テスト用）
- 入口の情報がない店は、ヒント3を決まり文句にして公開できるようにした
- 位置の精度待ち、日本時間での判定、7日の数え方、画面の向き、ヒント解放状態の保存、店リストの読み込みの待ち時間などを明確にした

## 0. 決定事項

### たまおが決めたこと

**店データと公開**

| 項目 | 内容 | 理由 |
|------|------|------|
| 店データの作り方 | Claude Codeが公式情報から店リストを作り、たまおが確認して公開する | Google Places APIの規約では、無期限に保存できるのは place_id だけ。座標は30日まで、店名・営業時間・レビューは保存不可 |
| 店データの出典 | Googleマップは出典にしない（確認のために見た場合も、店名・営業時間・座標などを書き写さない）。たまおが店に行って確かめたことは出典にしてよい | Googleマップのデータの保存・転記は規約違反になる。自分の体験は誰の規約にも縛られない |
| 掲載する店 | Googleマップに店舗として載っているシーシャ専門店。完全予約制・会員制の店、予約が必須の店、コンセプトカフェ・メイド業態の店は載せない。ただし、たまおが行って実態がそうでないと確かめた店は載せてよい。掲載取り下げの窓口は置かない | 予約なしで入れない店や、シーシャより接客が主の店は、ふらっとシーシャを吸いに向かうアプリの性質に合わない |
| 営業時間がはっきりしない店 | 決まった営業時間がない店は、曜日ごとの時間が書けるときだけ載せる。30:00（朝6時）を超えて営業する店は 30:00 と書く | 営業時間がわからないと、閉まった店に案内してしまう。30:00 で切ると早めに閉まる扱いになるだけで、閉まった店には案内しない |
| 最初に載せる区 | 豊島区・新宿区・渋谷区・港区（1区ずつ公開する） | よく行くエリアから始める |
| 作業用データの置き場所 | 非公開リポジトリ `mystery-navi-data`。公開リポジトリには `shops.json` だけを入れる | 店へのメモ、閉店などの判定、載せなかった店の一覧を公開しないため |
| 店データの持ち方 | 区名を持たせる。営業時間は曜日ごと、定休日あり、深夜は「26:00」表記 | 区は「地図で見る」の検索と将来の区ごとの進捗に使う。営業時間は1組だけだと定休日や曜日差を表せない |
| 報告フォーム | 置かない | 記録は端末の中だけ。営業時間の誤りは、たまおが気づいたときに店リストを直す |
| Googleマップへの自動投稿 | 実装しない | 実体験に基づかない投稿は規約上の削除対象。投稿用の公開APIも見当たらない |
| 収益化 | なし（アフィリエイト・特典欄も入れない） | まずアプリの完成を優先 |

**選び方**

| 項目 | 内容 | 理由 |
|------|------|------|
| 選ぶ店の営業時間 | 今営業中で、閉店まで残り75分を超える店だけ。開店直前の店も選ばない | 移動と1回分を吸う時間を確保する。近い店だと開店前に着いてしまう |
| すぐ近くの店 | 今いる場所から200m以内の店は選ばない | 店の中で開いたとき、今いる店や隣の店が選ばれると、歩かずに到着画面が出てしまう |
| 案内中の店 | 到着するまで、3時間は同じ店を案内し続ける | iPhoneは画面ロックやタブ切り替えでページが再読み込みされやすい |
| 「別のお店にする」 | ナビ画面から選び直せる。外した店は除外しない。他に候補があれば、直前の店はその1回だけ選ばない。行き先が変わったことを、矢印の動きと短い表示で知らせる | 方向と距離しか見えないので、変わったことがわからないと押した手応えがない |
| 未訪問の優先 | 未訪問の店と訪問済みの店の両方が近くにあれば、70%の確率で未訪問の店から選ぶ | 新しい店に出会いやすくしつつ、訪問済みの店も3回に1回くらいは出る |
| 未訪問の定義 | 記録が1件もない店。「行かなかった」「満席」だけの店も訪問済み | 店名を知っている店は、もう新しい店ではない |
| 評価した店 | どの評価でも、その日（朝5時まで）は選ばない | 今出てきた店に、その夜また案内されても意味がない |
| 閉店した店 | 案内しない（公開用データに入れない）。ただしトロフィーの回数は残す | 店リストの更新でトロフィーが下がるのを防ぐ |

**評価と矢印の色**

| 項目 | 内容 | 理由 |
|------|------|------|
| 評価の分け方 | 良い：お店良かった ／ 悪い：お店悪かった・入る気にならなかった・閉まっていた ／ ニュートラル：今日はやめておく・満席で入れなかった | 店の良し悪しと関係ない理由で、店の印象を下げないため |
| 「行かなかった」 | 押した後に理由を選ぶ：入る気にならなかった（悪い）／今日はやめておく（ニュートラル） | 店を見て入らなかったのは店への判定だが、疲れた・時間がないは店と関係ない |
| 「空いてなかった」 | 押した後に理由を選ぶ：閉まっていた（悪い）／満席・入れなかった（ニュートラル） | 「空く」と「開く」の2通りに読めるため |
| 点数 | 良い＋1、悪い−1、ニュートラル0を、店ごとにすべて合計する | 評価の積み重ねで色を決める。良かった店が一度閉まっていたくらいでは赤黒にならない |
| 矢印の色 | 点数がプラスならミント、0なら通常、マイナスなら禍々しい赤黒 | 前に評価した店が、矢印の色でわかる |
| 赤黒の見た目 | 深い赤から黒へのグラデーションに暗い赤の光をまとわせ、ゆっくり脈打たせる | 色だけでなく動きでも禍々しさを出す |
| 悪い店の扱い | 二度と選ばないのではなく、また案内する。ただし選ばれる確率は他の訪問済みの店の半分 | 矢印の色で「前に悪かった店」とわかる体験にする |
| 「閉まっていた」の後 | 7日間は選ばない | 臨時休業ならしばらく待つ。営業時間のデータが違うなら、その間に直す |
| 押し間違い | 評価の直後5秒だけ［取り消す］を出す。押すとその店の到着画面に戻る | 押し間違いはその場で気づくことが多い |

**到着**

| 項目 | 内容 | 理由 |
|------|------|------|
| 到着の判定 | 100m以内、かつGPSの誤差が60m以下。一度到着したら戻らない | GPSのブレで到着画面が出たり消えたりするのを防ぐ |
| 到着後の保持 | 到着したら「到着済み」を保存し、評価するまで到着画面を保つ（「到着した日（朝5時区切り）の翌朝5時」と「到着から3時間後」の遅いほうまで）。保持中はGPS・未到着の3時間の期限・営業時間を見ない | 吸い終わってから評価できるように。店の中はGPSの誤差が大きく、到着を判定し直せないことがある。朝5時の直前に着いても、3時間は評価できるようにする |
| 評価せずに別のお店へ | 到着画面に小さく置く。記録もトロフィーも残らない | 3月の「評価しなければ記録しない」と同じ動きを残す |
| ヒントの役割 | 1つ目は漠然と（500m）、2つ目は少し具体的に（300m）、3つ目は入口の見つけ方（到着画面で店名と一緒に出る。ビル名・階数も可）。入口の情報がない店は決まり文句にする | 近づくほど答えに近づき、着いたら入口まで迷わない。情報がない店も公開できるようにする |
| 地図で見る | 到着画面から、店名と区名でGoogleマップを開く | シーシャ屋は雑居ビルの上の階が多く、店名だけでは入口がわからない |
| 距離の表示 | 直線距離。「直線」とは書かない | 迂回すると矢印が回り、距離がなかなか減らない。その不便さも謎のコンパスに導かれる楽しさ |

**トロフィー**

| 項目 | 内容 | 理由 |
|------|------|------|
| 段階 | 到着した回数で7段階：5回アイアン（チュートリアル完了）・10回ブロンズ・20回シルバー・35回ゴールド・60回エメラルド・100回ダイヤ・150回ポラリス | 全店制覇は店リストを広げるほど遠のく。回数なら続けるほど必ず進む |
| 1回の数え方 | 到着画面で評価を記録したら1回（どの評価でも）。同じ店は1日1回まで | 歩かずに回数を稼げないようにする |
| 見せ方 | ナビ画面の隅にさりげなく表示。段階ごとに色と形を変える。タップで記録パネル | コンパスだけのミニマルな見た目を崩さない |
| 未獲得のトロフィー | 名前を「？？？」で伏せる。必要な回数は見せる | ミステリーのコンセプトに合わせる |
| 昇格のお知らせ | 一度だけ数秒表示し、「記録を書き出す」リンクを添える。見逃したら次に開いたときに出す | 隅のトロフィーが変わるだけだと気づかない。昇格をバックアップのきっかけにする |

**記録の保護・見た目・その他**

| 項目 | 内容 | 理由 |
|------|------|------|
| 記録の保護 | ホーム画面対応（PWA）＋記録のバックアップ。11章 | iPhoneのSafariは、7日間操作のないサイトの保存データを消す。ホーム画面に追加したWebアプリは対象外 |
| 起動画面 | アプリ名は出さない | 知らない人には何のアプリかわからない見た目にする |
| 方位の表記 | N・E・S・W（「画面の文言は日本語のみ」の例外） | コンパスらしい見た目を優先する |
| 画面のスリープ防止 | ナビ画面の間だけ、画面が自動で消えないようにする | 画面が消えるたびに起動画面からやり直す手間を減らす |
| 年齢の注意書き | 起動画面に「20歳未満の方はご利用いただけません」 | 案内先は喫煙を目的とした店で、20歳未満は入店できない |
| 歩きスマホの注意書き | 出さない | シーシャは大人の趣味 |
| コンパスの直し方 | 記録パネルにヘルプを置く（自動では出さない） | 磁石や鉄骨の近くでは方位が狂うことがある |
| ファイル構成 | 画面と計算を分け、計算には自動テストを付ける | 選び方や点数の不具合を、街を歩かなくても家で見つけられる |
| 開発中の画面確認 | 開発用にだけPlaywrightを入れ、Claude Codeが自分で画面を開いてスクリーンショットで確かめる（アプリ本体には入れない） | 見ていない画面を「確認した」と報告させないため |

### 提案（たまおの確認待ち。差し戻し可）

| # | 項目 | 内容 | 理由 |
|---|------|------|------|
| N1 | 行き先が変わったときの見せ方 | 矢印が1回転してから新しい方向で止まり、「行き先が変わりました」と数秒表示する。動きを減らす設定の端末では回転しない | 方向と距離しか見えない画面で、変わったことがひと目でわかる |
| N2 | 理由の文言 | 「行かなかった」の後：［入る気にならなかった］［今日はやめておく］［戻る］ | 押した人が、どちらが店への判定かを迷わない言い方にする |
| N3 | トロフィーの形 | 段階が上がるほど形を複雑にする。例：小さなメダル → リボン付きメダル → 盾 → 杯 → 宝石付きの杯 → カットされた宝石 → 光る星（ポラリス）。実装時にClaude Codeが3案出し、たまおが選ぶ | 色だけだと、小さなアイコンで段階を見分けにくい |

### 技術的に必須

| # | 項目 | 内容 | 理由 |
|---|------|------|------|
| T1 | Androidの方位 | 絶対方位のイベントを使う | 通常のイベントは端末ごとに基準がバラバラで、北を指さないことがある |
| T2 | 公開方法 | HTTPSで公開（GitHub Pages） | 位置情報・方位センサー・ホーム画面対応・画面のスリープ防止は、HTTPSでないと使えない |
| T3 | ブラウザからホーム画面への記録の移行 | 書き出し→読み込みで移す | iPhoneでは、ホーム画面のWebアプリとSafariは保存場所が別で、記録が引き継がれない |
| T4 | 時刻の判定 | 営業時間・朝5時の切り替え・「今日」の判定は、すべて日本時間（UTC+9）で行う | 端末のタイムゾーン設定に左右されないようにする。店の営業時間は日本時間 |

## 1. コンセプト

起動すると、近くのシーシャ専門店を1軒だけ選び、**方向と距離だけ**で案内する。店名は100m以内まで近づかないとわからない、ミステリーツアー型のWebアプリ。

- 見た目は、知らない人には「シーシャ屋に行くアプリ」だとわからないほどシンプルなコンパス
- 地図は出さない。距離は直線で、迂回すると矢印が回り、なかなか減らない。その不便さも楽しさのうち
- 前に評価した店は、矢印の色でわかる（良い店はミント、悪い店は禍々しい赤黒）
- 導かれて店にたどり着いた回数が増えるほど、トロフィーが上がっていく

## 2. 前提・範囲

| 項目 | 内容 |
|------|------|
| 形態 | スマホブラウザで動くWebアプリ。ホーム画面に追加して使うことを推奨（PWA） |
| 対象エリア | 東京23区（最初は豊島区・新宿区・渋谷区・港区） |
| 対象店舗 | シーシャ専門店のみ（バーや飲食店のついでシーシャ、完全予約制・会員制・予約必須の店、コンセプトカフェ・メイド業態の店は除外。7章） |
| アカウント | なし |
| 保存先 | 端末内のみ（localStorage）。バックアップは利用者が手動で書き出す |
| サーバー | なし（静的ファイルの配信だけ） |
| 外部API | 動作中は使わない（Googleフォントの読み込みと、Googleマップへのリンクのみ） |
| 位置情報 | 端末の外に送らない |
| UI言語 | 日本語のみ（方位の N・E・S・W だけ例外） |
| 画面の向き | 縦向きのみ |
| 公開 | HTTPSで配信（GitHub Pages） |
| 対象ブラウザ | iPhoneのSafari、AndroidのChrome（いずれも最新版） |

## 3. 画面一覧

| # | 画面 | 表示条件 |
|---|------|----------|
| S0 | 起動画面 | 毎回の起動時 |
| S1 | ナビ画面 | 案内する店が決まったとき |
| S2 | 到着画面 | 案内中の店に到着したとき。到着済みの案内先があるとき（到着判定は5章） |
| S3 | 圏外画面 | 近くに案内できる店がないとき |
| S4 | エラー表示 | 位置情報が拒否・取得できないとき |
| S5 | 記録パネル | トロフィーをタップしたとき |

### S0 起動画面

- アプリ名は出さない。コンパスのモチーフと「はじめる」ボタンだけ
- 「はじめる」を押した時点で、iPhoneの方位センサー許可（ユーザー操作が必須）と位置情報の取得を始める
- 「はじめる」の後は 4-1 の流れで、S1・S2・S3 のどれかに進む（到着済みの案内先があれば、位置を待たずにS2）
- 小さな注意書き
  - 「20歳未満の方はご利用いただけません」
  - 「位置情報はこの端末の中だけで使い、どこにも送信しません」
- **ブラウザで開いているとき**（ホーム画面から開いていないとき）だけ、案内を出す
  - 「ホーム画面に追加して使ってください。ブラウザのままだと、しばらく開かないうちに記録が消えることがあります」
  - 追加の手順を短く（iPhone：共有ボタン →「ホーム画面に追加」／Android：メニュー →「ホーム画面に追加」）
  - 「ブラウザで使っていた記録は、記録パネルの『書き出す』→ ホーム画面のアプリで『読み込む』で移せます」
  - 案内を出したままでも「はじめる」は押せる（ブラウザでも使える）

### S1 ナビ画面

- コンパス風の円形UI（方位のラベルは N・E・S・W）
- 矢印：店の方向を指し、端末の向きに合わせてリアルタイムで回る
  - 色は、その店の点数で決まる（6章）

    | 点数 | 色 |
    |------|-----|
    | 記録なし、または0 | 通常：ゴールドベージュ `#c8b89a` |
    | プラス | ミントグリーン `#7eb8a4` |
    | マイナス | 禍々しい赤黒（8章） |

- 矢印の下に距離（現在地から店までの直線距離。画面に「直線」とは書かない）
  - 1000m未満は10m単位で四捨五入して「350m」。丸めた結果が1000m以上なら km の小数1桁で「1.2km」
  - 例：347m → 350m、994m → 990m、995m → 1.0km、1234m → 1.2km
- ヒント欄（3枠）
  - 500m以内でヒント1、300m以内でヒント2が解放
  - 一度解放したヒントは、離れても、アプリを開き直しても隠さない（6章で保存）
  - 未解放の枠は「500m で解放」のように薄く表示。3つ目は「到着で解放」
- **トロフィー**（右上の隅に小さく）
  - 今の段階の色と形で表示（8章）。アイアン前は線だけの薄いアイコン
  - タップでS5（記録パネル）を開く
- **一時的なお知らせ**（コンパスの上に数秒だけ。S3でも同じ位置に出す）
  - 評価した直後（5秒）：「『お店悪かった』で記録しました」と［取り消す］（4-4）
  - 昇格したとき（取り消しの5秒が過ぎてから）：「ブロンズトロフィー」と、小さな「記録を書き出す」リンク（4-3）
  - 行き先が変わったとき：「行き先が変わりました」（4-2）
  - 位置の精度が低いまま店を選んだとき：「位置の精度が低いため、案内がずれることがあります」（4-1）
- **「別のお店にする」**（画面の下に小さな文字リンク）
  - 押すと確認：「今のお店をやめて、別のお店を探しますか？」［探す］［やめる］
  - 「探す」で選び直す（4-2）
- **画面のスリープ防止**：S1を表示している間だけ、画面が自動で消えないようにする（10章）
- 方位センサーが使えない端末：コンパスの N を画面の上に固定し、矢印は北を基準にした方角を指す。「北を上にして見てください」と表示

### S2 到着画面

- 店名
- 現在の距離
- ヒント3つすべて（3つ目は入口の見つけ方）
- 「地図で見る」ボタン
- 評価ボタン4つ
- 「評価せずに別のお店へ」（画面の下に小さな文字リンク）

|--------|------------|------|------|------|--------------------|
| お店良かった | — | `good` | 良い | ＋1 | その日 |
| お店悪かった | — | `bad` | 悪い | −1 | その日 |
| 行かなかった | 入る気にならなかった | `declined` | 悪い | −1 | その日 |
| 行かなかった | 今日はやめておく | `skip` | ニュートラル | 0 | その日 |

| 空いてなかった | 満席・入れなかった | `full` | ニュートラル | 0 | その日 |

ボタンの色：お店良かった `#7eb8a4`、お店悪かった `#b87e7e`、行かなかった `#8a8a9a`、空いてなかった `#b8a07e`

**到着画面を保つ**
- 到着画面は、評価するか「評価せずに別のお店へ」を押すまで出し続ける。「到着した日（朝5時区切り）の翌朝5時」と「到着から3時間後」の遅いほうを過ぎたら、記録を残さずに閉じて選び直す
  - 例：月曜23:00着 → 火曜5:00まで。火曜3:30着 → 火曜6:30まで。火曜5:01着 → 水曜5:00まで
  - 境目：朝5:00ちょうどは新しい日（捨てる）。到着から3時間ちょうどは保つ
  - 朝5時を過ぎてから評価した記録は、評価した時刻の日として数える
- アプリを開き直しても、GPSを使わずに到着画面に戻る（店の中でも評価できるように）
- 到着画面を保っている間は、3時間の期限と営業時間を見ない（閉店時刻を過ぎてから評価してもよい）

**理由の選択**（「行かなかった」「空いてなかった」を押したとき）
- その場に2つの理由と［戻る］を出す
- 理由を押したら記録する
- ［戻る］は何も記録せず、到着画面に戻る

**評価の記録ルール**
- 評価（理由の選択を含む）を確定した時点で初めて記録する。到着画面を開いただけでは何も記録しない
- 評価しなかった場合（「評価せずに別のお店へ」、到着画面の保持の期限を過ぎた）は、何も残さない（トロフィーの回数にも数えない）
- どの評価でも、トロフィーの回数に1回数える（同じ店は1日1回まで。4-3）
- 点数・矢印の色・選ばれやすさ・除外は、すべて記録から計算する（6章）

**「評価せずに別のお店へ」**
- 押すと確認：「評価せずに、別のお店を探しますか？」［探す］［やめる］
- 「探す」で 4-2 と同じ手順で選び直す（記録は残さない。この店はその1回だけ選ばない）

**「地図で見る」**
- 店名と区名でGoogleマップの検索を開く（`MAP_SEARCH_URL`。新しいタブ。iPhoneでは地図アプリが開くこともある）
- リンクを開くだけで、アプリがGoogleからデータを取得・保存することはない

評価を記録したら、次の店を選んでS1（候補がなければS3）に移り、取り消しのお知らせを出す。

### S3 圏外画面

- 到着した回数：`23回`

## 4. お店の選び方とトロフィー

### 4-1. 選び方

```
起動（「はじめる」を押す）
 ↓
保存中の案内先がある？（6章）
 ├─ 到着済み、かつ保持の期限（「到着した日（朝5時区切り）の翌朝5時」と「到着から3時間後」の遅いほう）を過ぎていない、かつ店がデータにある → S2（位置を待たない。営業時間・未到着の3時間の期限は見ない）
 ├─ 未到着、かつ3時間以内・除外中でない・今も営業中 → 位置を取ってS1を再開
 └─ それ以外 → 案内先を捨てて、以下で選ぶ
 ↓
現在地と現在時刻を取得
   ・誤差が100m以下になるまで最大10秒待つ
   ・待っても100mを超えるときは、そのときの位置で選び、「位置の精度が低いため、案内がずれることがあります」を出す
 ↓
① 現在地から200mより遠く、1km以内の店を抽出
   └─ 0件 → 1km以内に店がなければ S3-A1、200m以内にだけあれば S3-A2
 ↓
② 除外中の店を外す（6章）
   ・今日（朝5時切り替え）記録した店
   ・最後の「閉まっていた」から7×24時間以内の店
   └─ 0件 → S3-B
 ↓
③ 今営業中で、閉店まで残り75分を超える店に絞る（開店前の店は、開店直前でも選ばない）
   └─ 0件 → S3-C
 ↓
④ 2つのグループに分ける
   ・未訪問グループ：記録が1件もない店
   ・訪問済みグループ：記録がある店
 ↓
⑤ グループを選ぶ
   ・両方に店がある → 70%の確率で未訪問、30%で訪問済み
   ・片方だけ　　　 → そちら
 ↓
⑥ 選んだグループの中から1軒
   ・未訪問グループ：完全ランダム
   ・訪問済みグループ：点数がマイナスの店は、他の店の半分の確率になるように重みを付けて選ぶ
 ↓
S1 ナビ画面（案内先として保存）
```

- 距離はハバーサイン式で計算する
- 方角は、現在地から店への方位角（真北基準、時計回り）を計算する
- 時刻の判定（営業時間・朝5時の切り替え・「今日」）は、すべて日本時間（UTC+9）で行う。端末のタイムゾーン設定には左右されない
- 閉店までの残り時間は、隣り合う営業時間の範囲がつながっている場合（深夜の `29:00` と翌日の `05:00` 開始など）は、つなげて計算する
- 祝日の営業時間の違いは扱わない（ズレは、たまおが気づいたときに店リストを直す）
- 未到着の案内先を再開するときは、75分ルールと200mルールを使わない（案内中に条件を外れても、店を変えない）
- 閉店した店は公開用データに入っていないので、選ばれることはない

### 4-2. 「別のお店にする」「評価せずに別のお店へ」

S1の「別のお店にする」と、S2の「評価せずに別のお店へ」は、同じ手順で選び直す。

1. 確認で「探す」を押す
2. 保存中の案内先を消す（到着済みの状態も消える）
3. 現在地を取り直し、4-1 の①から選び直す
4. 直前の店は、他に候補があればこの1回だけ選ばない
5. 新しい店を案内先として保存する（3時間はここから数え直す）
6. 行き先が変わったことを知らせる
   - 別の店になった：矢印が1回転してから新しい方向で止まり、「行き先が変わりました」を数秒表示する。距離とヒント欄も新しい店のものに切り替わる
   - 候補がその店だけで、同じ店になった：「近くで案内できるお店はここだけです」を数秒表示する（回転しない）
   - 候補が1軒もない：S3
   - 端末で動きを減らす設定がオンのとき（`prefers-reduced-motion`）は、回転せず表示だけ出す

- 外した店は記録に何も残さない。除外もしない。点数にもトロフィーの回数にも関係しない

### 4-3. トロフィー

**回数の数え方**
- 到着画面で評価を記録するたびに1回（6種類の記録のどれでも）
- 取り消した評価は数えない
- 同じ店は、同じ日に何度評価しても1回まで（評価した店はその日選ばれないので、通常は起きない。念のための決まり）
- 日付は朝5時で切り替える（23時と翌2時は同じ日。4:59と5:01は別の日）
- 店リストから消えた店の分も、数えたまま残す
- 回数は保存せず、評価の記録（6章）から毎回計算する。数え方のルールを後で変えても、記録から数え直せる

**段階**

| 回数 | トロフィー | 意味 |
|------|------------|------|
| 0〜4 | なし（線だけの薄いアイコン） | チュートリアル中 |
| 5 | アイアン | チュートリアル完了 |
| 10 | ブロンズ | |
| 20 | シルバー | |
| 35 | ゴールド | |
| 60 | エメラルド | |
| 100 | ダイヤ | |
| 150 | ポラリス | 最上級 |

- 段階の回数と名前は定数で持つ（9章）。後から段階を足せるようにする
- 昇格したら、取り消しの5秒が過ぎてから一度だけお知らせを出す（S1かS3）。取り消して回数が戻った場合は出さない
- お知らせを見逃した場合（5秒以内にアプリを閉じたなど）は、次にS1かS3を表示したときに出す。判定は「今の段階」が「お知らせ済みの段階」より上かどうか
- お知らせを出した段階は記録しておき、同じお知らせを二度出さない
- 段階を2つ以上飛ばして上がったとき（デバッグで記録をまとめて追加したときなど）は、一番上の段階を1回だけお知らせする
- 記録の読み込みで段階が上がった場合は、お知らせを出さない

### 4-4. 取り消し

評価の直後5秒だけ、評価の後に出た画面（S1かS3）に［取り消す］を出す。

1. 直前に追加した評価の記録1件を消す
2. 次の店として選んだ案内先を捨て、評価した店を「到着済み」の案内先に戻す（到着した日時と解放済みのヒントも元に戻す）
3. その店の到着画面（S2）に戻る。正しいボタンを押し直せる

- 消せるのは直前の1件だけ。5秒を過ぎたら取り消せない（ちょうど5秒までは取り消せる）
- 消すのは、記録の末尾が評価のときに足した記録と同じ（店ID・値・日時が一致）ときだけ。間に記録の読み込みがあった、別のタブで記録が足されたなどで末尾が違うときは、何も消さない
- 取り消せるかどうかはメモリにだけ持つ。アプリを開き直したら、5秒以内でも取り消せない

## 5. 到着判定とヒント

| 条件 | 動き |
|------|------|
| 距離 500m以内 | ヒント1を解放 |
| 距離 300m以内 | ヒント2を解放 |
| 距離 100m以内、かつGPSの誤差（accuracy）が60m以下 | 到着。案内先に到着した日時を保存し、到着画面へ切り替える |

- 一度到着したら、GPSのブレで離れてもナビ画面に戻らない
- 到着後の扱いは S2「到着画面を保つ」
- 誤差が60mを超えている間は、「GPSの精度が下がっています」と小さく表示する
- 解放したヒントの数は、案内先と一緒に保存する（6章）
- 数値はすべて設定ファイルの定数にし、実地テストで調整する（9章）

## 6. 端末に保存するデータ

キー：`mysteryNavi.v1`

```json
{
  "schemaVersion": 1,
  "visits": [
    { "shopId": "shop_001", "value": "good",     "at": "2026-11-05T21:10:00+09:00" },
    { "shopId": "shop_002", "value": "closed",   "at": "2026-11-06T22:40:00+09:00" },
    { "shopId": "shop_001", "value": "good",     "at": "2026-11-12T20:30:00+09:00" },
    { "shopId": "shop_005", "value": "declined", "at": "2026-11-13T23:10:00+09:00" }
  ],
  "currentTarget": {
    "shopId": "shop_014",
    "selectedAt": "2026-11-14T20:05:00+09:00",
    "unlockedHints": 2,
    "arrivedAt": "2026-11-14T20:31:00+09:00"
  },
  "trophy": {
    "announcedLevel": "iron"
  },
  "lastExportAt": "2026-11-12T20:35:00+09:00"
}
```

**日時の形式**
- 保存は ISO 8601 の文字列。`Date.prototype.toISOString()` の形（UTC、末尾が `Z`）でよい。上の例は読みやすさのため日本時間で書いている
- 読み込み（バックアップと端末の保存データ）では、末尾が `Z` か `±HH:MM` の日時だけを受け付ける。時差の書かれていない日時（例：`"2026-11-10T03:30:00"`）は、端末のタイムゾーンで読まれて日付がずれるので受け付けない
  - 形：`YYYY-MM-DDTHH:MM:SS`（小数秒は1〜3桁まで省略可）＋ `Z` または `±HH:MM`
  - 存在しない日付・時刻（2月30日、`24:00:00`、時差 `+24:00` など）も受け付けない
- 受け付けた日時の文字列は、`Z` の形にそろえず、そのまま保存する
- 判定はすべて日本時間で行う（4-1）

**`visits`（評価の記録）**
- 評価を記録したときだけ、末尾に1件追加する
- 後から書き換えたり消したりしない。例外は3つだけ：取り消し（直前の1件・5秒以内。4-4）、記録の読み込み、デバッグのリセット
- 店リストから消えた店の記録も消さない。選び方では無視し、トロフィーの回数と記録パネルの数には数える

**記録の種類**

| 値 | ボタン → 理由 | 分類 | 点数 | トロフィーの回数 |
|----|---------------|------|------|------------------|
| `good` | お店良かった | 良い | ＋1 | 数える |
| `bad` | お店悪かった | 悪い | −1 | 数える |
| `declined` | 行かなかった → 入る気にならなかった | 悪い | −1 | 数える |
| `closed` | 空いてなかった → 閉まっていた | 悪い | −1 | 数える |
| `skip` | 行かなかった → 今日はやめておく | ニュートラル | 0 | 数える |
| `full` | 空いてなかった → 満席・入れなかった | ニュートラル | 0 | 数える |

**記録から決まること**（すべて保存せず、記録から毎回計算する）
- **同じ日**：日本時間の朝5時で切り替える（`DAY_BOUNDARY_HOUR`）
- **点数**：店ごとに、すべての記録の点数を合計する
  - 例：good、closed、good（すべて別の日）→ ＋1 −1 ＋1 ＝ ＋1 でミント
  - 例：good、declined → 0 で通常の色
- **矢印の色**：点数がプラスならミント、0か記録なしなら通常、マイナスなら赤黒
- **除外中**：次のどちらか
  - 今日（朝5時切り替え）記録がある店（どの評価でも）
  - 最後の `closed` の日時から7×24時間以内の店
- **グループ**：記録が1件もない店は未訪問、1件でもあれば訪問済み
- **選ばれやすさ**：訪問済みグループの中で、点数がマイナスの店は重み0.5、それ以外は1
- **トロフィーの回数**：同じ店・同じ日の記録を1回にまとめた件数（4-3）

**`currentTarget`（案内先）**
- `selectedAt`：店を選んだ日時
- `unlockedHints`：解放したヒントの数（0〜2）。解放したら書き込む
- `arrivedAt`：到着した日時。未到着なら `null`
- 店を選んだ時点で書き込み、評価したとき・「別のお店にする」「評価せずに別のお店へ」を押したときに消す。取り消したときは、評価した店（到着済み）に戻す
- 評価の記録ではなく、再読み込みで行き先が変わらないための一時的な記録
- 破棄して選び直す条件
  - 未到着のとき：3時間を超えた、店がデータから消えた、その店が除外中になった、その店が営業時間外になった
  - 到着済みのとき：「到着した日（朝5時区切り）の翌朝5時」と「到着から3時間後」の遅いほうを過ぎた、店がデータから消えた（営業時間と未到着の3時間の期限は見ない）

**その他**
- `trophy.announcedLevel`：お知らせを出した最高の段階。まだなければ `null`
- `lastExportAt`：最後に書き出した日時。まだなければ `null`
- localStorage が使えない環境（古いブラウザや、サイトデータの保存を止めている設定など）でも動く。その場合は保存せずに動かす。なお、今のiPhoneのプライベートブラウズでは保存できるが、タブを閉じると記録が消える（アプリからは見分けられない）
- 変更を書き込むときは、保存データを読み直してから変更を当てる（同じブラウザの別のタブの記録を上書きしないため）
- 端末の保存データを書き戻すときは、読める記録も読めない記録も、知らない項目も含めて元の形のまま残す。項目を捨てるのはバックアップの読み込み（11章）のときだけ

**保存データが読めないとき**（どの場合もアプリは止めない）

| 状況 | 扱い |
|------|------|
| JSONとして読めない、オブジェクトでない、`schemaVersion` がない・1より小さい・数値でない、`visits` が配列でない | 壊れたデータ。元の文字列を加工せずに `mysteryNavi.v1.broken.<退避した日時>` に退避してから、空の状態で始める。退避先の名前に日時を入れ、前の退避を上書きしない。退避できなかったときは、元のデータを上書きしないよう、保存せずに動かす |
| `schemaVersion` が1より大きい | 新しい版のアプリのデータ。退避も上書きもせず、保存せずに動かす（サービスワーカーのキャッシュで古い版のアプリが一時的に動いたときに、新しい版のデータを壊さないため） |
| 使っている途中で、保存データが壊れたデータや新しい版のデータになった（別のタブなど） | その時点から保存せずに動かす |
| 一部の記録だけが読めない（店ID・値（6種類）・日時の形が決まりに合わない） | その記録を保存データに元の位置のまま残し、選び方・点数・トロフィーの計算と書き出しから外す |
| 案内先・`trophy.announcedLevel`・`lastExportAt` が読めない | それぞれ「なし」（`null`）として扱う |

- 退避したデータはアプリが消さない。デバッグパネルで中身を見られる（12章）
- 退避して空で始めたときは、S1かS3で「保存データが読めなかったため、新しく記録を始めます。前のデータは端末に残してあります」を一度出す（次に開いたときは、もう退避は起きないので出ない）
- 保存せずに動いているとき、または書き込みに失敗したとき（容量オーバーなど）は、記録パネル（S5）に「この端末では記録を保存できていません」と出す

## 7. 店データ（shops.json）

```json
{
  "dataVersion": "2026-11",
  "updatedAt": "2026-11-05",
  "shops": [
    {
      "id": "shop_001",
      "name": "シーシャ屋〇〇",
      "ward": "渋谷区",
      "lat": 35.6580,
      "lng": 139.7016,
      "hours": {
        "mon": ["18:00-26:00"],
        "tue": [],
        "wed": ["18:00-26:00"],
        "thu": ["18:00-26:00"],
        "fri": ["18:00-29:00"],
        "sat": ["15:00-29:00"],
        "sun": ["15:00-24:00"]
      },
      "hints": [
        "夜が深くなるほど落ち着くお店",
        "カウンター越しに会話が生まれるお店",
        "雑居ビルの4階。エレベーターは建物の奥にあります"
      ]
    }
  ]
}
```

**載せる店**
- シーシャ専門店で、Googleマップに店舗として載っている店（載っているかは、たまおが目で確かめる）
- 載せない店：完全予約制・会員制の店、予約が必須の店、コンセプトカフェ・メイド業態の店、バーや飲食店のついでにシーシャを出す店
  - 例外：たまおが行って、実態がそうでない（予約なしで入れる、コンセプトカフェ・メイド業態ではない など）と確かめた店は載せてよい
- 決まった営業時間がない店（不定期営業など）は、曜日ごとの時間が書けるときだけ載せる。書けなければ載せない
- 閉店した店は載せない（記録とトロフィーの回数は端末に残る）

**出典**
- 店の公式サイト・公式SNSなどの公式情報を使う
- **Googleマップは出典にしない。** 確認のために見た場合も、店名・営業時間・座標・口コミなどを書き写さない
- たまおが店に行って確かめたこと（営業時間、入口の様子など）は出典にしてよい
- 出典の記録は `mystery-navi-data` に置き、このリポジトリには置かない

**区（ward）**
- 東京23区の区名のいずれか（例：`渋谷区`）
- 「地図で見る」の検索に使う。将来の区ごとの進捗にも使う

**営業時間のルール**
- `"HH:MM-HH:MM"` の範囲を配列で持つ（昼休みがある店は2つ）
- 空配列は定休日
- 日をまたぐ営業は、**前日の営業として24:00以降の時刻で書く**（翌2時閉店なら `"18:00-26:00"`。最大 `30:00`）
- 30:00（朝6時）を超えて営業する店は、終わりを `30:00` と書く（翌8時閉店なら `"18:00-30:00"`）。アプリでは朝6時に閉まる扱いになり、選ぶときの「閉店まで75分」も早めに効くだけで、閉まった店に案内することはない
- 24時間営業は、毎日 `"00:00-24:00"` と書く（隣り合う範囲としてつなげて扱う）
- 判定は「今日の範囲」と「昨日の範囲を24時間ずらしたもの」の両方を見る（日本時間）

**ヒントのルール**
- 3つ
  - ヒント1（500mで解放）：雰囲気など漠然と
  - ヒント2（300mで解放）：もう少し具体的に
  - ヒント3（到着画面で店名と一緒に出る）：**入口の見つけ方**。階数、ビルの見た目、入口や看板の位置、エレベーターか階段か など
- ヒント1・2には、店名・住所・ビル名・その店だけが使う固有名詞を書かない
- ヒント3は店名と同時に出るので、ビル名や階数を書いてよい（店名・住所は書かない）
- 入口の情報が見つからない店は、ヒント3を決まり文句「入口の情報はまだありません。『地図で見る』で確かめてください」にして公開してよい。たまおが行ったときに書き換える
- 店の評判を下げる表現は書かない（中立か前向き）
- 口コミサイトの文章をそのまま使わない

**このリポジトリにあるのは公開用の `shops.json` だけ。** 下書き・出典・確認メモなどの作業用データは、非公開リポジトリ `mystery-navi-data` にある。そこで作った `shops.json` をこのリポジトリに書き出す。

**テストは `shops.json` を使わない。** テスト用のダミー店は `tests/fixtures/` に別に持つ（店リストを本物に替えてもテストが壊れないように）。

## 10. センサーと画面の扱い（技術メモ）

**方位**
- iPhone：`DeviceOrientationEvent.requestPermission()` を「はじめる」ボタンの中で呼ぶ。方位は `webkitCompassHeading` を使う
- Android：`deviceorientationabsolute` イベントを使い、方位は `360 - alpha`
- 矢印の角度 ＝ 店への方位角 −（端末の方位 ＋ `DECLINATION_DEG`）
- 画面が横向きになったときは、画面の回転角（`screen.orientation.angle`。古いiPhoneは `window.orientation`）の分だけ補正する
- 値がブレるので軽く平滑化する。359度→0度の境目で矢印が一回転しないようにする

**位置**
- `watchPosition` で追い続ける（`enableHighAccuracy: true`）
- 店を選ぶ前は、誤差が `INITIAL_ACCURACY_M` 以下になるまで最大 `INITIAL_FIX_TIMEOUT_SEC` 秒待つ（4-1）

**画面のスリープ防止**
- S1を表示したら `navigator.wakeLock.request('screen')` をかける。`try/catch` で包み、使えない端末や断られたときは何もしない
- S1以外に移るときに解除する
- アプリが裏に回ると自動で解除されるので、表に戻ってS1なら（`visibilitychange`）かけ直す
- iPhoneのホーム画面アプリでは iOS 18.4 以降で効く（それより前は効かないが、エラーにはしない）

## 11. ホーム画面対応とバックアップ（技術メモ）

**なぜ必要か**
- iPhoneのSafariは、操作のない日が7日続いたサイトの保存データ（localStorage など）を消す。トロフィーは何か月もかけて貯めるので、消えると取り返しがつかない
- ホーム画面に追加したWebアプリは、この削除の対象外
- ただし、iPhoneではホーム画面のWebアプリとSafariは保存場所が別。ブラウザで貯めた記録は、書き出し→読み込みで移す

**ホーム画面対応（PWA）**
- `manifest.webmanifest`
  - 名前（13章で決める）、`display: "standalone"`、`orientation: "portrait"`、背景色とテーマ色は `#0a0a0f`
  - アイコン：192px・512px、iPhone用に180pxの `apple-touch-icon`
  - `start_url` と `scope` は相対パス（`./`）。GitHub Pagesはリポジトリ名のサブパスで公開されるため
- `sw.js`（サービスワーカー）
  - アプリ本体（HTML・CSS・JS・アイコン）はキャッシュを使う。バージョンを上げたら新しいキャッシュに入れ替える
  - `shops.json` はネットワークを先に見る。3秒で応答がないとき、またはつながらないときは、キャッシュを使う（店リストの更新がすぐ届き、地下などでも待たされないように）
  - Googleフォントはキャッシュしなくてよい（読み込めなければ端末のフォント）
- 起動時に `navigator.storage.persist()` を呼ぶ（対応していない端末では何もしない）
- ホーム画面から開いているかの判定：`matchMedia('(display-mode: standalone)')` または `navigator.standalone`

**バックアップ**
- 書き出す内容：`{ "app": "mystery-navi", "schemaVersion": 1, "exportedAt": "…", "visits": [ … ] }`
  - 案内中の店は入れない。位置情報も入らない（店IDと日時と評価だけ）
- 書き出し：文字列をクリップボードにコピーし、「メモアプリなどに貼り付けて保存してください」と添える。コピーできない端末では、文字列を選択できる形で表示する
- 読み込み
  - 貼り付けられた文字列を検査する（`app` の名前、`schemaVersion`、各記録の店ID・値（6章の6種類のどれか）・日時の形式（6章））。前後の空白・改行は無視する
  - 店IDは、64文字以内の空でない文字列なら受け付ける（`shop_001` の形までは縛らない。IDの付け方を変えても古いバックアップを読めるように）
  - 店リストにない店IDの記録も受け付ける（閉店した店の記録があるため）
  - 1件でも検査に通らない記録があれば、何も変えずにエラーを出す
  - 記録は店ID・値・日時の3項目だけを取り込み、余分な項目は捨てる
  - 通ったら「今の記録（23回）を、読み込む記録（5回）で上書きします。よろしいですか？」と、トロフィーの回数を添えて確認してから置き換える
  - 置き換える前に、今の保存データを加工せずに `mysteryNavi.v1.beforeImport.<日時>` に退避する。退避できなければ置き換えずにエラーを出す
  - 置き換えたら、お知らせ済みの段階を今の段階に合わせる（お知らせを連続で出さない）
  - 置き換えたら、案内先は消す（起動画面からやり直す）。`lastExportAt` は変えない
- 書き出したら `lastExportAt` を更新する
- 一部の記録が読めない（6章）ときは、読める記録だけを書き出す。読めない記録を入れると、その書き出しが読み込みの検査に通らなくなるため

## 12. デバッグモード

URLに `?debug=1` を付けたときだけ表示する、家でテストするためのパネル。

- 現在地を入力して上書き（緯度・経度、店の近くへワープするボタン）
- 端末の向きを上書き（スライダー）
- 現在時刻を上書き（営業時間判定・日付切り替えのテスト用）
- 評価の記録をまとめて追加（回数を指定。日付は1日ずつずらす）。トロフィーのテスト用
- 指定した店に評価の記録を1件追加（値と日時を選ぶ）。矢印の色と除外のテスト用
- **仮の目的地**：緯度・経度を入れると、その地点を店の代わりに案内する。実機でセンサーを確かめるため（Phase 7）
  - 名前は「仮の目的地」。端末の中だけに保存し、`shops.json` には書かない
  - 着いたら到着画面の代わりに「仮の目的地に着きました（◯m）」を出す。評価の記録・トロフィー・点数には関係しない
  - 矢印の色を選べる（通常・ミント・赤黒）。屋外での見え方を確かめるため
  - 解除ボタンで通常の案内に戻る
- 保存データの表示とリセット
  - リセットは確認してから行う。リセットの前に、今の保存データを加工せずに `mysteryNavi.v1.beforeReset.<日時>` に退避する。退避できなければリセットしない
  - 退避したデータ（`mysteryNavi.v1.broken.…`・`mysteryNavi.v1.beforeImport.…`・`mysteryNavi.v1.beforeReset.…`）も一覧で見られ、中身をコピーできる。消すボタンは付けない

デバッグはブラウザで `?debug=1` を付けて開く。iPhone ではホーム画面のアプリとブラウザの保存場所が別なので、デバッグで記録を変えてもホーム画面のアプリの記録には影響しない。Android では同じ保存場所なので、デバッグの記録の追加・リセットは本番の記録を変える。

デバッグで入れる位置は、駅などの公共の場所にする。たまおの自宅などの位置を、コードやテストや画像に残さない（公開リポジトリのため）。
