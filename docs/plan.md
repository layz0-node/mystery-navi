## 始める前に、たまおがやること

### 1. GitHubにリポジトリを2つ作る（専用アカウントで）

| リポジトリ | 公開設定 | 役割 |
|------------|----------|------|
| `mystery-navi` | **公開**（GitHub Pagesを無料で使うため） | アプリ本体と公開用の `shops.json` |
| `mystery-navi-data` | **非公開** | 店リストの作業用データ（出典・メモ・確認リスト） |

- **README・.gitignore・ライセンスは付けず、空で作る**（zipの中身と重なるため）
- このGitHubアカウントでは、他のGitHub Pagesを作らない。同じアカウントのページは、アプリの記録の保存場所を共有してしまうため
- 公開リポジトリなので、要件定義と開発計画も誰でも読める（困る内容は入っていない）

### 2. 専用Macに開発の道具を入れる（ターミナルで）

```bash
# Homebrew（Mac用の道具の管理ツール）を入れる。gitなどの基本の開発ツールも一緒に入る
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
# ↑ 最後に表示される「Next steps」のコマンド（2行ほど）をそのまま実行する

# Node.js（テストに使う）と GitHub CLI（GitHubの操作に使う）を入れる
brew install node gh

# GitHubにログインする（ブラウザが開くので、専用アカウントでログイン）
# 質問には GitHub.com → HTTPS → Yes → Login with a web browser の順に答える
gh auth login

# コミットに付ける名前とメールアドレス（メールは下の noreply アドレス）
git config --global user.name "（GitHubのユーザー名）"
git config --global user.email "（noreplyアドレス）"
```

**メールアドレスについて**：公開リポジトリでは、コミットに付けたメールアドレスを誰でも見られる。先にGitHubの Settings → Emails で「Keep my email addresses private」と「Block command line pushes that expose my email」をオンにし、そこに表示される `〜@users.noreply.github.com` のアドレスを使う。

わからないところがあれば、Claude Codeに「Homebrew・Node.js・GitHub CLIの準備を手伝って」と頼んでもかまいません。

### 3. 2つのリポジトリを同じ親フォルダにクローンする

```bash
mkdir -p ~/dev && cd ~/dev
gh repo clone （GitHubのユーザー名）/mystery-navi
gh repo clone （GitHubのユーザー名）/mystery-navi-data
```

```
~/dev/
├── mystery-navi/        ← 公開
└── mystery-navi-data/   ← 非公開
```

2つが隣り合っていることが前提です（お互いを `../` で参照します）。

### 4. zipの中身を置く（Finderではなくターミナルで）

```bash
cd ~/dev
unzip ~/Downloads/mystery-navi.zip
ls -a mystery-navi mystery-navi-data
```

- `unzip` すると、2つのリポジトリに一度にファイルが入る
- `ls -a` で、`mystery-navi` に `.gitignore`、`mystery-navi-data` に `.gitignore` と `.claude` が見えれば成功
- **Finderでコピーしない。** `.gitignore` と `.claude` は隠しファイルで、Finderでは見えずにコピーし忘れやすい。漏れると、次の2つがなくなる
  - 公開側（`mystery-navi`）の `.gitignore`：作業用データ（`data/`・`*.master.json`・`review.md`）やスクリーンショットを誤って公開しないための安全装置
  - 非公開側（`mystery-navi-data`）の `.claude`：店リスト作成スキル

### 5. その他

- 3月に作った画面設計（`screen-design.html`）が手元にあれば `mystery-navi/docs/` に入れる。なくても `requirements.md` の色とフォントで足りる

## Phase 1：店を選ぶロジック・点数・トロフィーの集計

**目的**：仕様の4章・5章・6章「記録から決まること」「currentTarget」・7章を、画面なしで正しく動かす。

**指示**
```
Phase 1 を進めてください。requirements.md の4章・5章・6章（記録から決まること、currentTarget の破棄条件）・7章を
src/logic.js に純粋な関数として実装し、tests/ にテストを書いてください。
乱数と現在時刻は引数で渡す形にしてください。時刻の判定は日本時間で行ってください。
```

**実装する関数のイメージ**（名前はClaude Codeに任せてよい）
- 2点間の距離（m）
- 現在地から店への方位角（真北基準）
- ある時刻（日本時間）に営業中か、閉店まで何分あるか
- 朝5時切り替えの「日付」（日本時間）
- 評価の記録から、店ごとの点数・矢印の色・除外中か・グループ（未訪問・訪問済み）
- 保存中の案内先を、再開するか・到着画面を出すか・捨てるかの判定
- 選出：店リスト・評価の記録・現在地・現在時刻・乱数・（直前に外した店）→「どの画面を出すか」と「選んだ店」
- トロフィーの集計：評価の記録 → 回数・今の段階・次の段階まであと何回・訪れた店の数・良い店の数・悪い店の数
- 距離と保存済みの解放数から、ヒントの解放数と到着かどうか
- 距離の表示文字列（350m／1.2km）

**テストで必ず確かめるケース**

営業時間と時刻
- 月曜 `"18:00-26:00"` の店が、火曜 1:30 に営業中と判定される
- 定休日（空配列）の日は営業していない
- 閉店まで残り75分の店は選ばれない。残り76分の店は選ばれる
- 開店10分前の店は選ばれない
- 24時間営業（毎日 `"00:00-24:00"`）の店は、閉店間際と判定されない
- 同じ時刻をUTCで渡しても、日本時間で判定される（例：UTCの月曜16:30 ＝ 日本時間の火曜1:30）

点数と矢印の色
- good 1件 → ＋1・ミント
- good・closed（別の日）→ 0・通常色
- good・closed・good（すべて別の日）→ ＋1・ミント
- bad 1件 → −1・赤黒
- declined 1件 → −1・赤黒
- good・declined → 0・通常色
- skip・full だけ → 0・通常色
- 記録なし → 通常色

除外
- 今日（朝5時切り替え）記録した店は、どの評価でも選ばれない。翌朝5:00以降は選ばれる
- `closed` から167時間後は除外、169時間後は選ばれる（7×24＝168時間）
- `bad` の店も、翌日以降は選ばれる

案内先の再開
- 未到着：3時間以内・除外中でない・営業中なら再開。3時間を超えたら捨てる
- 到着済み：3時間を超えていても、閉店時刻を過ぎていても、到着画面を出す
- 到着済み：「到着した日の翌朝5時」と「到着から3時間後」の遅いほうを過ぎたら捨てる（記録は増えない）
- 店がデータから消えていたら、到着済みでも捨てる

グループと選ばれやすさ
- 記録が1件もない店は未訪問グループ。skip だけの店は訪問済みグループ
- 両方のグループに店があるとき、グループを選ぶ乱数が 0.69 なら未訪問、0.71 なら訪問済みから選ばれる（`UNVISITED_PICK_RATE` が 0.7 のとき）
- 片方のグループにしか店がないときは、乱数に関係なくそちらから選ばれる
- 訪問済みグループに点数プラスの店Aと点数マイナスの店Bがあるとき、Bが選ばれる確率が1/3になる（重み 1 と 0.5）
- 乱数を固定すると、同じ店が選ばれる

距離の条件
- 200m以内の店は選ばれない。201m〜1000mの店は選ばれる
- 店が200m以内にしかないときは S3-A1 ではなく S3-A2、1km以内に1軒もないときは S3-A1

別のお店にする
- 直前に外した店は、他に候補があれば選ばれない
- 候補がその店だけなら、同じ店が選ばれ、「ここだけ」の状態が返る

画面の判定
- 圏外A1・A2・B・Cが、それぞれ正しい条件で出る
- 近くの店がすべて除外中なら S3-B
- 近くの店が、残り75分以内の店や開店前の店だけなら S3-C

ヒント
- 解放済みの数は、離れても減らない（保存値と、今の距離から決まる数の大きい方）

トロフィー
- 6種類どの記録も1回に数える
- 同じ店を23:00と翌2:00に評価 → 1回（同じ日）
- 同じ店を4:59と5:01に評価 → 2回（別の日）
- 別の店なら同じ日でも別々に数える
- 店リストから消えた店の記録も数える
- 回数4でなし、5でアイアン、9でアイアン、10でブロンズ、20でシルバー、149でダイヤ、150でポラリス
- 「次の段階まであと何回」が正しい。ポラリスでは「最上級」になる
- 訪れた店の数は、同じ店を何回評価しても1軒。店リストから消えた店も含む

方位・距離・到着
- 方位：真北・真東の店で 0度・90度前後になる
- 距離：緯度を0.01度ずらすと約1112mになる
- 到着：100m以内でも、GPS誤差が60mを超えていれば到着にしない

**完了条件**：上のケースがすべてテストになっていて、通る。

**たまおの確認**：テスト一覧を読み、仕様と食い違うケースがないか。

## Phase 2：端末への保存・取り消し・バックアップ

**目的**：仕様の6章、4-3（お知らせの判定）、4-4、11章のバックアップを実装する。

**指示**
```
Phase 2 を進めてください。requirements.md 6章、4-3 のお知らせの判定、4-4、11章の「バックアップ」を
src/storage.js に実装し、localStorage の代わりになるメモリ上の模擬ストレージでテストしてください。
```

**テストで必ず確かめるケース**

保存
- 評価を追加すると記録の末尾に1件増え、読み直せる。既存の記録は変わらない
- 保存データが壊れていたら、元の文字列を別のキーに退避してから空の状態で始まる。退避できなければ保存しないで動く
- `schemaVersion` が1より大きい保存データは、退避も上書きもしない
- 読めない記録が混ざっていても止まらず、計算からは外れ、保存データには元の形のまま残る
- 時差の書かれていない日時は、読み込みで受け付けない
- localStorage が使えない環境でもエラーで止まらない
- 案内先の解放済みヒントの数と到着した日時が保存され、読み直しても残る
- 「別のお店にする」「評価せずに別のお店へ」で案内先が消え、評価の記録は何も変わらない
- 店リストにない店IDの記録は消えない

取り消し
- 評価から5秒以内の取り消しで、直前の1件だけが消え、案内先が評価した店（到着済み・解放済みヒントも元どおり）に戻る
- 5秒を過ぎると取り消せない。直前より前の記録は消せない

昇格のお知らせ
- 回数が段階に達したとき、お知らせが必要と判定される。一度出したら二度目は出ない
- 取り消しで回数が段階を下回ったら、お知らせは出ない
- お知らせを出さずにアプリを閉じても、次に開いたときにお知らせが必要と判定される

バックアップ
- 書き出して読み込むと、評価の記録が完全に元に戻る（6種類すべてを含む記録で確かめる）
- 書き出した中身に、案内中の店と位置情報が入っていない
- 日時が `Z` の形でも `+09:00` の形でも読み込める
- 店リストにない店IDの記録も読み込める
- 壊れた文字列、別のアプリの文字列、値が6種類以外の記録を含む文字列は、読み込みを拒否し、今の記録を変えない
- 読み込み後、お知らせ済みの段階が今の段階になり、お知らせが出ない

**完了条件**：テストが通る。

## Phase 4：起動画面とナビ画面

**目的**：S0とS1を作る。

**指示**
```

トロフィーと「別のお店にする」はコンパスより目立たせないでください。
トロフィーの形は、8章の案をもとに3案を作り、7段階を並べた見本ページで見せて、私に選ばせてください。
```

**完了条件**（すべて `?debug=1` で確認し、スクリーンショットを付ける）
- デバッグで店の方向に向きを合わせると、矢印が真上を指す
- 方位のラベルが N・E・S・W
- デバッグで記録を足すと、矢印の色が通常・ミント・赤黒に切り替わる

- 候補が1軒だけなら、回転せず「ここだけ」の表示が出る
- 「やめる」では何も変わらない
- トロフィーが、回数に応じた段階の色と形で表示される（デバッグで記録を追加して確認）
- 起動画面にアプリ名が出ていない
- ブラウザで開くと、起動画面にホーム画面への追加の案内が出る
- 幅390px前後のスマホ表示で崩れない
- 方位センサーがない場合は N を上に固定した表示になる

## Phase 5：到着・評価・圏外・エラー・記録パネル

**目的**：S2〜S5、「行かなかった」「空いてなかった」の理由選択、到着画面を保つ仕組み、取り消し、昇格のお知らせを作る。

**指示**
```
Phase 5 を進めてください。requirements.md 3章の S2〜S5 と、4-2（評価せずに別のお店へ）、4-3 の昇格のお知らせ、4-4 の取り消しを実装してください。
確認した画面は、Playwright でスクリーンショットを撮って報告に付けてください。
```

**完了条件**（`?debug=1` で確認し、スクリーンショットを付ける）
- 100m以内に入ると到着画面に切り替わり、GPS誤差を悪化させても戻らない
- 到着画面で再読み込みすると、位置に関係なく到着画面に戻る。時刻を3時間後・閉店後にしても到着画面のまま。「到着した日の翌朝5時」と「到着から3時間後」の遅いほうを過ぎると選び直しになる
- 到着画面に3つ目のヒント（入口の見つけ方）が出る。決まり文句の店でも表示が崩れない
- 「地図で見る」で、店名と区名で検索したGoogleマップが開く
- 6通りの評価（理由の選択を含む）がそれぞれ正しく記録され、次の店に切り替わる
- 「行かなかった」「空いてなかった」→「戻る」で、何も記録されずに到着画面に戻る
- 「評価せずに別のお店へ」→ 確認 →「探す」で、記録が増えずに別の店に切り替わる
- 評価した直後に、今いる店や200m以内の店、今日評価した店が次の行き先にならない
- 評価直後の［取り消す］で到着画面に戻り、押し直せる。5秒たつと消える
- 評価の直後に圏外画面になっても、［取り消す］と昇格のお知らせが出る
- 昇格のお知らせは、取り消しの5秒が過ぎてから出る。5秒以内に再読み込みしても、次に表示したときに出る
- 圏外A1・A2・B・C、位置情報拒否の表示を、デバッグで再現できる
- 記録パネルの数字（回数・訪れた店・良い店・悪い店）が合っている。未獲得のトロフィー名は「？？？」で、「次のトロフィーまで」にも名前が出ない
- 記録パネルの「矢印の向きがおかしいとき」が開いて読める
- 書き出し→リセット→読み込みで記録が戻る
- 読み込みの確認に「今の記録（◯回）を、読み込む記録（◯回）で上書きします。よろしいですか？」と回数が出る
- 保存データを壊して開くと（`storage.js` の `status().recoveredKey` が入る）、S1かS3に「保存データが読めなかったため、新しく記録を始めます。前のデータは端末に残してあります」が一度出る。開き直すともう出ない
- 保存できないとき（`status().saving` が false、または `status().lastWriteFailed` が true）、記録パネルに「この端末では記録を保存できていません」が出る

**このフェーズで決めること**
- 位置が1回も取れないまま何秒たったら S4（エラー表示）に切り替えるか。Phase 3 では、最初の位置が来るまで待ち続け、`watchPosition` のエラーが来たときだけ S4 に進む作りにしてある（`INITIAL_FIX_TIMEOUT_SEC` の10秒は「精度を待つ」時間で、1回も取れないときの打ち切りではない）

## Phase 8：本番の店リスト作成（mystery-navi-data で作業）

## 公開後の運用

| 頻度 | やること | リポジトリ |
|------|----------|------------|
| 「閉まっていた」に当たったとき | 営業時間の変更や閉店がないか、その店を見直す（`/update-shop-list`） | mystery-navi-data（`--add-dir ../mystery-navi` で起動） |
| 四半期に1回 | 新店の追加と閉店の確認（`/update-shop-list`） | 同上 |
| 昇格したとき | 記録を書き出しておく（機種変更や誤操作に備える） | — |
| 気が向いたら | 対象の区を広げる。区ごとの進捗画面を作る（requirements.md 13章） | 両方 |

**更新を公開するときの注意**：店リストを変えただけなら、`sw.js` のバージョンを上げる必要はない（`shops.json` は毎回ネットワークを先に見る）。画面やロジックを変えたときは、`sw.js` のバージョンを上げる。どちらも push しないと公開サイトに反映されない。
